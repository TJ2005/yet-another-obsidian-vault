# Security Fatigue

> [!DEF] Furnell & Thomson
> "There is a threshold at which it simply gets too hard or burdensome for users to maintain security. When this fatigue happens, people become **desensitised** and grow **weary**."

## What happens

- Security demands are a **cognitive load** on users
- Past the personal threshold → users stop weighing decisions at all
- Result: clicking through warnings, reused passwords, ignored prompts
- The failure is **design-induced**, not malicious
- Compounds every other [[Humans in Cybersecurity|human weakness]]
- Reference: Stanton, Theofanos, Prettyman & Furman (2016), *Security Fatigue*, IT Professional 18(5)

## How to overcome

| Strategy | Mechanism |
| --- | --- |
| **Security by design** | Secure defaults remove decisions entirely |
| **Limit security decisions** | Fewer choices per user = less burden before the threshold |
| **Make the right choice simple** | Low friction on the secure path so System 1 lands safely |
| **[[SETA Program]]** | Well-designed training sustains attention instead of numbing it |
| **Developing security culture** | Shared norms make secure behaviour automatic, not effortful |
